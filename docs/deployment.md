# Deployment guide — Clinique Physio Mont-Royal

How the system is hosted, how to deploy it from nothing, and every setting it reads.
Day-to-day operations (backups, key rotation, redeploy, problems): [runbook.md](runbook.md).
Architecture: [architecture.md](architecture.md). API reference: https://clinique-physio-api.onrender.com/docs
(generated by FastAPI; a copy is kept in [openapi.json](openapi.json)).

## 1. Where everything runs

| Part | Host | Plan and place | Deployed by |
|---|---|---|---|
| Database (PostgreSQL 16 + pgvector) | Neon | Free, AWS us-east-1 (Virginia) | Migrations run by the API at start |
| API (FastAPI) | Render, from `render.yaml` | Free web service, Virginia (next to the database) | Automatically, when the deployment copy changes |
| Website (React) | Vercel, folder `web` | Hobby, global CDN | Automatically, when the deployment copy changes |
| Desktop app (WPF, front desk) | GitHub Releases | Windows installer | By hand, for each version tag |
| Mobile app (Expo, patients) | Expo / APK | Android | By hand (EAS build or Expo Go link) |
| Online payments | Stripe | **Test mode (Sandbox) only** | Keys in Render |
| Chatbot AI | OpenAI | Pay per use (a few cents per day of demo) | Key in Render |

Work happens in `stevatak/Khadizhat-Synth`. Render and Vercel deploy from the deployment copy
`kkprojects5/clinique-physio`, updated after each merge with `git push deploy main`
([ADR-0006](adr/0006-deployment-copy.md)). The copy is never edited directly.

```
branch → pull request → CI green → merge → git push deploy main → Render + Vercel deploy
```

## 2. Deploying from nothing

Do these once, in this order. Every secret goes in the host's settings, never in the repository.

### 2.1 Database (Neon)

1. Create a Neon project in **AWS US East 1**, PostgreSQL 16, database `neondb`.
2. Copy the connection string (**Connection details → psql**, pooled off). It contains the
   password: keep it in a password manager, never in a file in the repository or in a chat.
3. Nothing else: the first API start creates the extensions (`btree_gist`, `vector`) and all
   tables.

### 2.2 API (Render)

1. Render → **New → Blueprint**, choose the deployment copy. Render reads `render.yaml`.
2. Fill the values marked `sync: false` (table in section 3): `DATABASE_URL`,
   `FIELD_ENCRYPTION_KEY`, `ALLOWED_ORIGINS`, the Stripe keys and `OPENAI_API_KEY`.
   `JWT_SECRET` is generated by Render.
3. Deploy. The start command applies the migrations (`alembic upgrade head`), loads the chatbot
   passages and their embeddings (`python -m app.chatbot.ingest`), then starts the API.
4. Check: https://clinique-physio-api.onrender.com/health answers `{"status":"ok"}`.

### 2.3 Website (Vercel)

1. Vercel → **Add New → Project**, choose the deployment copy, **Root Directory: `web`**
   (Vite is detected).
2. Environment variable: `VITE_API_URL = https://clinique-physio-api.onrender.com`.
3. Deploy. `web/vercel.json` adds the security headers (CSP, HSTS, COOP) and sends every page
   to `index.html`.
4. Put the site address in the API's `ALLOWED_ORIGINS` and `WEB_BASE_URL` (Render), and in the
   CSP `connect-src` and `img-src` of `web/vercel.json` if the API address changes.

### 2.4 Stripe (test mode)

1. Stripe dashboard in **Sandbox**: **Developers → API keys**: copy the secret and publishable
   keys to Render.
2. **Developers → Webhooks → Add endpoint**:
   `https://clinique-physio-api.onrender.com/api/v1/webhooks/stripe`, events
   `payment_intent.succeeded` and `payment_intent.payment_failed` (refunds are made by the API
   itself, so no refund event is needed).
   Copy its signing secret (`whsec_…`) to `STRIPE_WEBHOOK_SECRET`.
3. Test card: `4242 4242 4242 4242`, any future date, any CVC.

### 2.5 Demo data

From a computer with the code, once, with `DATABASE_URL` pointing to Neon for this command
only (then put your local value back):

```
cd api
python -m app.seed                          # staff, services, hours, fictional patients
python -m app.seed --refresh-appointments   # appointments for the next two weeks
```

The demo passwords come from `SEED_STAFF_PASSWORD` and `SEED_PATIENT_PASSWORD`. They are given
to the supervisor privately, never written in the README.

### 2.6 Desktop app

1. `desktop/src/CliniquePhysio.Desktop/appsettings.json`: `ApiBaseUrl` is the API address
   (already the live API).
2. Build the installer for a version (section 4 of the runbook) and attach it to the GitHub
   release.

### 2.7 Mobile app

`mobile/.env`: `EXPO_PUBLIC_API_URL` and `EXPO_PUBLIC_WEB_URL` (both default to the live
addresses). For the demo, share the app with Expo Go (`npx expo start --tunnel`, then scan the
QR code); the Android APK for the release is built with EAS (runbook section 4).

## 3. Environment variables

### 3.1 API (`.env` locally, Render settings in production)

| Variable | Required | Production value | Purpose |
|---|---|---|---|
| `DATABASE_URL` | Yes | Neon connection string (secret) | PostgreSQL. `postgresql://` is changed to the `psycopg` driver automatically |
| `JWT_SECRET` | Yes | Generated by Render (secret) | Signs access tokens (10 minutes). Rotation: runbook 3.1 |
| `FIELD_ENCRYPTION_KEY` | Yes | Fernet key (secret); `new,old` during a rotation | Encrypts clinical notes, emergency contacts and MFA secrets. Rotation: runbook 3.2 |
| `ENVIRONMENT` | No | `production` | `development`, `test` or `production` |
| `ALLOWED_ORIGINS` | Yes in production | `https://clinique-physio.vercel.app` | Websites allowed to call the API (CORS), comma-separated |
| `WEB_BASE_URL` | No | `https://clinique-physio.vercel.app` | Links in emails (confirmation, password reset, invitation) |
| `COOKIE_SECURE` | No | `true` (default) | Refresh cookie over HTTPS only. `false` only for local http |
| `COOKIE_SAMESITE` | No | `none` | The website and the API are different sites; the cookie stays httpOnly and Secure |
| `STRIPE_SECRET_KEY` | No | `sk_test_…` (secret) | Empty: online deposit switched off |
| `STRIPE_PUBLISHABLE_KEY` | No | `pk_test_…` | Sent to the browser for the card form |
| `STRIPE_WEBHOOK_SECRET` | With Stripe | `whsec_…` (secret) | Checks that webhooks come from Stripe |
| `CURRENCY` | No | `cad` | Currency of payments |
| `OPENAI_API_KEY` | No | `sk-…` (secret) | Empty: the chatbot answers with keyword search only |
| `OPENAI_CHAT_MODEL` | No | `gpt-5.4-mini` | Model that words chatbot answers |
| `OPENAI_EMBEDDING_MODEL` | No | `text-embedding-3-small` | Model for the passage vectors (changing it: run the ingest again) |
| `OPENAI_TIMEOUT_SECONDS` | No | `15` | After this, the chatbot falls back to keyword search |
| `CHAT_MIN_SIMILARITY` | No | `0.30` | Minimum similarity for an embedding match |
| `PRIVACY_POLICY_VERSION` | No | `2026-10` | Change with the policy text (`web/src/pages/policyText.js`): patients are asked to accept again |
| `ACCESS_TOKEN_MINUTES` | No | `10` | Access token lifetime |
| `REFRESH_TOKEN_DAYS_PATIENT` | No | `7` | Patient session lifetime |
| `STAFF_INACTIVITY_MINUTES` | No | `15` | Staff logged out after this time without activity |
| `RATE_LIMIT_ENABLED`, `MAX_FAILED_LOGINS`, `LOCKOUT_MINUTES` | No | `true`, `5`, `15` | Brute-force protection |
| `EMAIL_VERIFICATION_HOURS`, `PASSWORD_RESET_MINUTES`, `STAFF_INVITE_HOURS` | No | `24`, `30`, `72` | Lifetime of the links sent by email |
| `SEED_STAFF_PASSWORD`, `SEED_PATIENT_PASSWORD` | Only for `app.seed` | Not set on Render | Demo account passwords (at least 12 characters) |

Generate the keys:

```
python -c "import secrets; print(secrets.token_urlsafe(48))"                                  # JWT_SECRET
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"    # FIELD_ENCRYPTION_KEY
```

### 3.2 Website (`web/.env`, Vercel settings)

| Variable | Value | Purpose |
|---|---|---|
| `VITE_API_URL` | `https://clinique-physio-api.onrender.com` | Address of the API, read at build time (public, not a secret) |

### 3.3 Mobile (`mobile/.env`)

| Variable | Value | Purpose |
|---|---|---|
| `EXPO_PUBLIC_API_URL` | `https://clinique-physio-api.onrender.com` | Address of the API (public) |
| `EXPO_PUBLIC_WEB_URL` | `https://clinique-physio.vercel.app` | The password reset page opens on the website |

`EXPO_PUBLIC_` values are built into the app and visible to anyone: never put a secret there.

### 3.4 Desktop (`appsettings.json`)

| Setting | Value | Purpose |
|---|---|---|
| `ApiBaseUrl` | `https://clinique-physio-api.onrender.com/` | Address of the API. The staff password is never saved; tokens are kept in memory only |

### 3.5 CI (GitHub Actions)

No repository secret is needed. The test and scan jobs create a throwaway database and use
throwaway values written in the workflow files (`ci-only-…`, `zap-only-…`), never a real key.

## 4. After every deployment

1. `/health` answers `ok` (the free plan sleeps after 15 minutes: the first call can take
   about 50 seconds).
2. The website opens and the services list loads (the API and CORS work).
3. Log in as a patient and open **Mes rendez-vous** (database and cookies work).
4. Ask the chatbot "Où puis-je me garer ?" (passages and AI work; without AI, the passage is
   shown as written).
5. In Render → **Logs**: no `ERROR` at start, and the line `alembic … upgrade` shows the
   expected migration.
